# Enemy Randomizer RMM Bridge

The bridge makes the launcher-owned `Launch modded copy` path use the selected dedicated `DRAKS0005.rmm` while loading recipient-generated Item/Enemy Randomizer content. It does not move, patch, download, or redistribute the Enemy Randomizer executable, its Mod Engine fork, or `DS1HeapPatch.dll`.

## Runtime layout

- Keep the recipient-supplied `DS1EnemyRandomizer` directory intact beneath the active copied runtime's `Mods` directory, either directly or below one package directory.
- Keep `DarkSoulsItemRandomizer.exe`, `DS1EnemyRandomizer.exe`, `config_randomizer.toml`, `dist1`, and `param` in the layout documented by `INSTALL_KO.md`.
- The launcher installs the project-owned bridge pair at `<external-root>\components\rmm-bridge` and resolves the selected save as `<external-root>\saves\<SteamID>\DRAKS0005.rmm`.
- Exactly one `DS1EnemyRandomizer.exe` installation may exist below the active runtime's `Mods` tree.

## Regeneration and launch

Run Item Randomizer first and export its changes into the active copied runtime. Run Enemy Randomizer last with `Merge files from game directory` enabled. `config_randomizer.toml` is generated by Enemy Randomizer and can be overwritten by `Randomize!`.

Do not use Enemy Randomizer's `Launch DS1` button for the integrated release flow. Return to DSR for MOD and use `Launch modded copy`. The launcher installs or repairs only the packaged project bridge/host, verifies both hashes and the strict deployment manifest, and writes `<external-root>\staging\diagnostics\config-randomizer-bridged.toml`. The generated configuration requires the recipient-supplied `DS1HeapPatch.dll`, retains the Randomizer mod path, and adds the project bridge exactly once.

`scripts/publish-rmm-bridge.ps1` is a developer deployment tool, not a recipient installer. Ordinary recipients do not need to run it or edit `config_randomizer.toml` by hand.

## Failure and rollback

Put Steam in Offline Mode before launching. A bridge/bootstrap, GameParam merge, or save-isolation failure stops the copied game; it never falls back to a normal `.sl2`.

For a temporary rollback, close the game and bridge host and launch the original game from Steam instead. For removal, preserve any private `.rmm` the recipient wants to keep, then remove only the recipient-selected external root, extracted project package, and local selection pointer as described in `INSTALL_KO.md`. Deleting only `<external-root>\components\rmm-bridge` is not a permanent rollback because the launcher repairs the project bridge on the next integrated launch.
